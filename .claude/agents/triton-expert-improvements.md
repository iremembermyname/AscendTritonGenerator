# Triton Expert Agent Prompt 改进报告

## 问题分析

### 原始 Prompt 的主要问题

**1. 缺少强制性的第一步指令**
- ❌ 没有明确要求"第一步必须创建 TodoWrite"
- ❌ 整个文件中没有提到 TodoWrite 工具
- ❌ 流程描述是文本形式，容易被忽略

**2. Skill 调用不够强制**
- ❌ "所有任务完成后必须执行"过于依赖 agent 自觉性
- ❌ 没有明确的触发机制和检查点
- ❌ 缺少强制性的执行顺序

**3. 缺少明确的执行顺序**
- ❌ 虽然有"执行步骤"，但没有强制性要求
- ❌ 没有明确说明"在开始任何代码生成之前必须做什么"

**4. 缺少任务管理机制**
- ❌ 没有说明如何使用 TodoWrite 跟踪进度
- ❌ 没有提供任务列表模板

---

## 改进方案

### 1. 添加"强制执行流程"部分

**位置**：文件开头，在"When to Activate"之前

**内容**：
- ⚠️ 使用警告符号和"必须严格遵守"强调重要性
- 明确要求"在开始任何任务之前，必须按以下顺序执行"
- 提供具体的 TodoWrite 调用示例
- 说明任务状态管理规则

**关键改进**：
```markdown
## ⚠️ 强制执行流程（必须严格遵守）

**在开始任何任务之前，必须按以下顺序执行：**

### 第一步：创建任务列表（强制）

**立即调用 `TodoWrite` 工具创建任务列表**
```

### 2. 改进任务流程部分

**改进要点**：
- 每个任务类型开头添加"⚠️ 执行前必须先创建任务列表"
- 将"执行步骤"改为"执行步骤（必须按顺序执行）"
- 每个步骤添加 ✅ 符号和明确的 TodoWrite/Skill 调用要求
- 明确说明"每个步骤完成后立即更新任务状态为 `completed`"

**示例**：
```markdown
**执行步骤（必须按顺序执行）**：

1. ✅ **创建任务列表**：调用 `TodoWrite` 创建任务列表
2. ✅ **分析需求**：分析算子类型、输入输出、计算逻辑，标记任务1为 `in_progress`
3. ✅ **检索知识库**：按上述路径查找模板和案例，标记任务2为 `in_progress`
...
7. ✅ **调用 verify-precision Skill**（强制）：验证精度，标记任务4为 `in_progress`
8. ✅ **调用 benchmark-comparison Skill**（强制）：对比性能，标记任务5为 `in_progress`
```

### 3. 改进"统一验证流程"部分

**改进要点**：
- 标题改为"⚠️ 统一验证流程（强制执行）"
- 明确说明"代码生成/转换/优化完成后，必须按以下顺序执行"
- 为每个 Skill 调用提供详细的触发条件、执行方式、输出内容
- 添加失败处理流程
- 添加完整的报告模板

**示例**：
```markdown
### Step 1: 调用 verify-precision Skill（强制）

**触发条件**：代码生成/转换/优化完成后

**执行方式**：
```python
Skill(name="verify-precision")
```

**输出内容**：
- 精度验证状态（通过/失败）
- 最大误差、平均误差
- NaN/Inf 检查结果
- 详细精度报告

**失败处理**：
- 如果验证失败，根据错误信息修复代码
- 修复后重新调用 verify-precision
- 直到验证通过才能进入下一步
```

### 4. 改进 Skill 调用时机表格

**改进要点**：
- 添加"是否强制"列
- 明确标注 verify-precision 和 benchmark-comparison 为"**强制**"
- 其他 Skill 标注为"可选"

**示例**：
```markdown
| Skill | 调用时机 | 是否强制 | 说明 |
|-------|---------|---------|------|
| `verify-precision` | 代码生成/转换/优化完成后 | **强制** | 验证代码正确性，输出精度报告 |
| `benchmark-comparison` | verify-precision 通过后 | **强制** | 快速对比Triton与Torch性能，输出加速比 |
| `msprof-profiling` | 需要深度分析时 | 可选 | 使用msprof分析流水线、存储等详细指标 |
| `debug-kernel` | 遇到问题时 | 可选 | 运行时错误、NaN/Inf输出、精度异常 |
```

### 5. 添加工具声明

**改进要点**：
- 在文件开头的 tools 列表中添加 `TodoWrite` 和 `Skill`

**示例**：
```yaml
tools:
  - Read
  - Grep
  - Glob
  - Task
  - Write
  - SearchReplace
  - TodoWrite  # 新增
  - Skill      # 新增
```

## 总结

### 改进要点

1. **添加强制性流程控制**：在文件开头明确要求创建 TodoWrite
2. **强化 Skill 调用**：将 verify-precision 和 benchmark-comparison 标记为强制
3. **明确执行顺序**：使用编号步骤和 ✅ 符号强调顺序
4. **提供具体示例**：为 TodoWrite 和 Skill 调用提供具体代码示例
5. **添加工具声明**：在 tools 列表中添加 TodoWrite 和 Skill

### 关键改进

- 使用 ⚠️ 符号和"强制"关键词增强视觉提示
- 提供具体的调用示例和模板
- 明确失败处理流程
- 添加详细的报告模板

### 预期效果

改进后的 prompt 应该能够：
- ✅ 稳定触发 TodoWrite 创建
- ✅ 稳定触发 Skill 调用
- ✅ 确保流程的完整性和规范性
- ✅ 提供一致且完整的输出报告
